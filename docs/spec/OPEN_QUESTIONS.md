# Неопределённости и управляемые допущения

Этот список запрещает агентам заполнять пробелы в ТЗ молча. Решение по пункту оформляется ADR, контрактом или профилем данных и получает владельца.

## G0 — требуется для общего контракта

| ID | Неопределённость | Почему опасно | Временное правило |
|---|---|---|---|
| `OPEN-001` | Формат входных геоданных и CRS | Несовместимые координаты дают физически неверные маршруты | Контракт обязан явно хранить CRS; внутренняя проекция выбирается ADR |
| `OPEN-002` | Единицы параметров БВС, ветра, заряда, высоты и времени | Скрытые пересчёты ломают физику и API | Единица указывается в имени/схеме каждого числового поля |
| `OPEN-003` | Численные профили БВС и полезной нагрузки | Ссылки есть, но единая таблица для модели не предоставлена | Профили версионируются с источником, датой и допущениями |
| `OPEN-004` | Семантика разрешённого пространства, бесполётных зон и резервных площадок | Неясны 2D/3D границы, буферы и обязательность резервной посадки | Не объявлять маршрут допустимым без документированной трактовки |
| `OPEN-005` | Точная схема KML/GeoJSON и кодирование этапов, высот и скоростей | Файл может открываться, но терять задание | Зафиксировать export contract и round-trip тест |
| `OPEN-006` | Определения двух целевых метрик | Разные формулы дают разные «оптимальные» планы | Пока использовать командную формализацию `Cmax` и сумму длительностей, помечая её как `TEAM-DECISION` |

## Физическая и съёмочная модель

| ID | Неопределённость | Риск для разработки/питчинга |
|---|---|---|
| `OPEN-007` | Учитывается только скорость ветра или полный вектор | Попутный/встречный ветер нельзя различить по одному модулю |
| `OPEN-008` | Модель энергии и допустимый резерв заряда | Нельзя честно заявлять физическую выполнимость маршрута |
| `OPEN-009` | Связь вида съёмки, сенсора, GSD, высоты, перекрытия и скорости | Геометрическое покрытие ещё не доказывает качество данных |
| `OPEN-010` | Разрешено ли сочетать несколько видов съёмки в одной задаче | Меняет совместимость БВС/полезной нагрузки и каталог кандидатов |
| `OPEN-011` | Требуются ли повторные вылеты одного БВС | Меняет расписание, зарядку и обе метрики |
| `OPEN-012` | Рельеф, AGL/ASL и вертикальные ограничения | Плоская модель не универсальна и должна быть объявлена ограничением |
| `OPEN-013` | Коллизии и минимальное безопасное сближение | Нельзя обещать безопасный совместный запуск без формальных правил |

## Производительность и качество оптимизации

| ID | Неопределённость | Временное правило |
|---|---|---|
| `OPEN-014` | Размеры обязательных сценариев и лимит времени | Публиковать собственные размеры и полный бюджет расчёта |
| `OPEN-015` | Требуется ли доказанный optimum | На малых задачах сравнивать с exact baseline; на больших говорить «лучшее найденное» |
| `OPEN-016` | Допустимое прореживание каталога | Потерю решения из-за pruning не называть физической невозможностью |
| `OPEN-017` | Эталонные данные и веса экспертных критериев | Не изобретать итоговый балл или SLA |

## Продукт и эксплуатация

## Правило заявления результата

Прохождение внутренних тестов доказывает работоспособность нашей модели в заявленной области допущений. Оно не доказывает универсальную оптимальность, безопасность реального полёта или совместимость с техникой Геоскана без отдельной проверки.
