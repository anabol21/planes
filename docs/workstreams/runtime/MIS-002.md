# MIS-002 — внешний перебор площадок и БВС

Адресат: агент Миши. Сначала прочитать `docs/architecture/OPTIMIZER_CORE.md`.

## Правила этого брифа

- Ветка от `main`. Контракт `v0`.
- Секреты, токены, адреса машин и URL с учётными данными не коммитить.
- Чужой шов не трогать: `geometry`, `precompute`, MILP, метаэвристика, `routes_raw`, `route_builder`, `validator`.
- Дедлайн показа: 25 сентября 2026, 21:00 Europe/Moscow.
- После показа код сшивает отдельная задача. Этот бриф сшивку не делает.

## Goal

Задание фиксирует зону, спектр, критерий и параметры оптимизации. Пользователь задаёт площадки. Снаружи ядра перебрать пары (модель БВС, камера) из справочника, у которых спектр камеры содержит `required_spectrum`, на каждой площадке. Каждый допущенный кандидат — один вызов ядра `run_core(InputData) -> dict` из протокола. Ядро вызывается как есть.

Зона на весь перебор одна. Пути `zone_constraints.kml_path` и `terrain.kml_path` фиксированы. Эти KML не парсить.

## Inputs and assumptions

- Протокол ядра: `docs/architecture/OPTIMIZER_CORE.md`.
- Один вызов по-прежнему содержит один `takeoff` и один объект `uav` с полем `count`.
- Из формы в конверт уходят зона (`area`), `required_spectrum`, `criterion` (`min_time` / `min_flight_hours`) и параметры оптимизации: лимит времени, ветер, общий профиль `gsd_cm_per_px`, `survey`, `power_coeffs`.
- Пользователь задаёт площадки, не больше 4: `id`, `lat`, `lon`, `count`. Координаты по умолчанию `37.6000`, `55.7470`, `count` = 1. `uav.count` в вызове равен `count` площадки.
- Поля `required_camera` и `uav_types` из задания уходят. Числа модели и камеры читаются из `src/planes/runtime/catalog/fleet_catalog.json`.
- Пул — рёбра `compatibility` от камеры, в `spectra` которой есть `required_spectrum`, к модели БВС. Кандидат — тройка `(pad, uav_model, camera)`. Порядок: площадки как ввёл пользователь, затем рёбра справочника.
- Пара без всех пяти полей `_OPTICS`, либо без одного числа `airspeed_m_s`, `battery.energy_wh` и остальных полей `_FLIGHT`, в `run()` не идёт. Пропуск записывается: id модели, id камеры, каких полей нет. Пустые клетки не заполняются.
- Нет выполнимой пары: ядро не вызывается, причина `no runnable uav and camera for spectrum`.
- Рабочая гипотеза независимых вызовов действует только до показа 25 сентября. `count` площадки применяется к испытываемой модели целиком. Сравнение кандидатов читает расход, который ядро уже возвращает: `mission.uav_used`, время миссии, `routes[].energy_breakdown_wh`.

## Масштаб перебора

Перебор на этом показе допустим только в такой границе:

- зона одна, задана до перебора;
- спектр, критерий и параметры оптимизации фиксированы, перебор их не меняет;
- площадок не больше 4;
- кандидат — тройка (площадка, модель БВС, камера) после фильтра спектра и полноты листа;
- один кандидат — один вызов ядра;
- выполнимых троек не больше 16; больше — явная ошибка, хвост не отбрасывается.

Внутри вызова остаются ограничения ядра, включая порог MILP `N≤3`, `M≤20`. Перебор эти пороги не сдвигает.

## Deliverables

1. Модуль перебора в `src/planes/runtime/enumeration/`. Он собирает `InputData` кандидата и вызывает чистую функцию ядра.
2. Фикстур пула в границе масштаба выше и детерминированный тест `tests/runtime/test_mis002*.py`.
3. На каждый успешный вызов сохранены `uav_used`, время и энергия из словаря `output.json`.
4. Строка статуса в `docs/status/runtime.md` со ссылкой на этот бриф.

## Acceptance criteria

- Число выполнимых вызовов не больше 16, площадок не больше 4. Свыше 16 — ошибка.
- Каждый вызов передаёт один `takeoff` и один `uav`. `uav.count` равен `count` площадки.
- KML зоны и KML местности не читаются этим модулем.
- Импортов, которые меняют `geometry`, `precompute` или солверы, нет.
- Одинаковые пул, зона и seed дают одинаковый набор кандидатов и одинаковый порядок вызовов.
- Расход успешного вызова берётся из существующих полей протокола.

## Explicitly out of scope

- Перешивка VPS, `infra/**`, слушатель и деплой. `solver.solve` только выбирает внешний путь и пишет в ограничения id площадки, модели и камеры.
- Сшивка вызовов в один план при общем пуле бортов и камер.
- Снятие приближений «один вылет», «постоянный ветер», «один GSD», «одинаковые борта внутри вызова».
- Правка MILP, метаэвристики, `route_builder`, `validator`, ключей `pre` и контракта `routes_raw`.

## Dependencies and consumers

- Вход: фиксированная зона и два пути KML, как в протоколе. Потребители швов — Гриша (`GRI-002`) и Руслан (`RUS-002`).
- Выход перебора — набор словарей ядра. Их соединяет отдельная задача после показа.
- `solver.solve` по-прежнему не меняет тело солвера. Для конверта с `pads` и `required_spectrum` он возвращает один лучший вызов. Конверт с `uav_types` отклоняется. Одиночный `takeoff` и `uav` остаются на одном вызове и справочник не читают.
- Бэкенд по-прежнему только пересылает `scenario`. `src/planes/contracts/` этот бриф не меняет.

## Risks / decisions required

- Гипотеза независимых вызовов ломается, когда борта и камеры делятся между вылетами. Решение о сшивке здесь не принимается.
- Правило пула — спектр камеры из справочника и полнота чисел для текущего ядра, без новой оптической модели. Сейчас до ядра доходит только Gemini + PF1B на RGB.
