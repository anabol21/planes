## Goal

Provide a reproducible execution boundary that accepts the versioned compute request, runs a placeholder or real optimization core on the VPS, and returns a structured response to the backend port.

## Deliverable

1. Runtime adapter implementing `OptimizationEngine` semantics.
2. Explicit process/container boundary and serialization format.
3. Timeout, cancellation/termination, exit-code, and stderr handling.
4. Health check and correlation by `job_id`.
5. Structured logs without secrets.
6. VPS setup/deploy/runbook and local fallback.
7. Smoke test using the shared fixture and, when available, Grisha's core.

## Acceptance

- The same request fixture runs locally and on VPS.
- Success, invalid response, crash, and timeout map to distinct outcomes.
- Backend tables are never edited directly by the runtime.
- Deployment is reproducible from a clean checkout.
- Secrets are supplied outside Git and never printed in logs.

## Boundary

Runtime owns how computation is executed and observed. Ruslan owns when a job is queued/claimed; Grisha owns the mathematical computation.
