## Goal

Render a completed feasible mission result as a React satellite map. The authoritative route line
is `mission_plan.routes[].waypoints[]`, in array order. The browser must not rerun the optimizer,
reconstruct routes from swaths, or parse KML.

## Allowed paths

- `apps/web/**`

- `docs/status/web.md`

## Scope

- Add minimal typed v0 result models for mission routes, waypoints, areas, obstacles, and supported
  constraint polygons.
- Convert each flight to one GeoJSON LineString using `[longitude, latitude]` without rounding,
  reordering, or deduplication.
- Render satellite imagery, survey areas, obstacles, supported constraints, route lines, start/base
  markers, route details, and a per-UAV legend inside the existing result page.
- Assign presentation colors in the frontend by `uav_id`; all flights of one UAV share a color.
- Fit the viewport to the available authoritative result geometry.
- Preserve existing lifecycle, polling, result-summary, infeasible, timed-out, and failed behavior.
- Add deterministic adapter, component, typecheck, and build verification.

## Team decisions

- MapLibre GL JS with `react-map-gl/maplibre` is the React map implementation because the current
  frontend has no map library and this stack consumes GeoJSON directly without iframe state.
- The demo raster source is Esri World Imagery with visible attribution and no committed API key.
  Production use remains subject to a separate provider-terms review.
- Altitude remains present in the typed waypoint input but is intentionally not rendered in this
  two-dimensional task.

These are implementation decisions, not customer requirements.

## Explicitly out of scope

- Optimizer, runtime solver, routing, assignment, terrain, KML generation, or backend changes.
- Route reconstruction, route geometry mutation, altitude profiles, 3D terrain, or UAV animation.
- A public contract-version change.

## Acceptance criteria

- One route produces one LineString with exact input order and `[lon, lat]` coordinate order.
- Multiple UAVs and multiple flights render as separate route features; UAV colors are stable.
- Consecutive duplicate XY waypoints are preserved.
- Feasible empty-route results display an explicit empty state.
- Infeasible, timed-out, and failed results do not display a fake map.
- Areas and valid obstacle polygons render without obscuring the satellite imagery.
- Constraint polygons render only when their geometry is explicitly supported.
- Bounds derive from result geometry rather than hardcoded coordinates.
- Frontend tests, typecheck, build, workspace validation, and `git diff --check` pass.
