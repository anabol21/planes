## Problem and minimal repair

In Chrome, a generated 1,800,000-byte KML with 224,966 altitude coordinates
in one outer ring passes upload but throws `RangeError: Maximum call stack
size exceeded` in `Math.max(...altitudes)`. Preview and submit both stop in
`buildPrototypeScenario` before fetch. The coordinate count is a regression
case, not a customer requirement or a new input limit.

Compute the maximum finite parsed altitude in one pass, without spreading
an array or allocating an intermediate altitude array. Preserve null for
absent/invalid altitudes, negative heights, and signed-zero maximum semantics.
Keep raw KML and every public v0 field unchanged. Do not alter HTTP-001,
backend/runtime, optimizer, terrain, schemas, or preview architecture.
