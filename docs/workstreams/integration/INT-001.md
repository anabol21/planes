## Goal

Allow the backend worker to execute a claimed job through the existing runtime VPS adapter while preserving backend lifecycle ownership and runtime transport ownership.

## Allowed paths

- `src/planes/backend/runtime_engine.py`
- `src/planes/backend/worker.py`
- `tests/backend/**`
- `docs/workstreams/integration/INT-001.md`
- `docs/status/integration.md`
- `docs/status/backend.md`

## Scope

- Convert backend-local v0 requests into runtime-local v0 requests using runtime-owned parsing.
- Invoke `RuntimeEngineAdapter.solve` without copying or replacing its HTTP behavior.
- Convert runtime responses back into backend responses without embedding runtime log contents.
- Preserve feasible, infeasible, timed-out, and error semantics.
- Select `fake` or `runtime` explicitly at the worker CLI, with `fake` as the default.
- Keep runtime adapter injection available for deterministic tests.

## Acceptance criteria

- Backend submission remains generic; runtime-specific optimization validation occurs only in runtime mode.
- `optimization.objective` is a non-empty string and `optimization.time_limit_seconds` is numeric and non-negative in runtime mode.
- Fake-only fields such as `test_outcome` are not passed into the runtime request.
- Feasible and infeasible responses complete the backend job, timed-out remains distinct, and runtime errors fail the job.
- Invalid runtime settings and adapter exceptions become structured backend failures, never infeasible outcomes.
- Runtime artifact references survive conversion; runtime log contents and secrets are not copied into backend storage.
- Existing fake behavior and backend tests remain valid.
- Tests make no real runtime HTTP requests.
- A real VPS smoke is performed only when all required out-of-band environment variables are already present.

## Boundary

Backend owns queueing, claiming, persistence, and lifecycle. Runtime owns HTTP transport and remote compute response construction. This task changes neither runtime internals nor solver logic.
