# INT-003 — TER-GRI terrain integration and OpenTopography acquisition

## Goal

Import the exact modern Grisha optimizer snapshot from `grisha_source_sha` onto current `dev`, then integrate the terrain semantics proven by TER-001 into that optimizer without merging either divergent source history. Add an integration-owned callable that acquires one COP30 GeoTIFF for a survey-area bounding box and returns a validated local cache path. The optimizer remains a pure offline consumer of local terrain files.

This task does not change public backend, runtime, frontend, or `v0` contract payloads.

## Requirement slice and managed OPEN items

The integration supports `REQ-PROD-002`, `REQ-PLAN-001..004`, `REQ-OUT-001..003`, `REQ-OUT-006`, `REQ-OPT-001..003`, `REQ-DOC-001..003`, `REQ-DOC-006`, `REQ-DELIV-F-001..002`, and `REQ-DELIV-F-004..005`.

It depends on `OPEN-001`, `OPEN-002`, `OPEN-003`, `OPEN-004`, `OPEN-007`, `OPEN-008`, `OPEN-009`, `OPEN-012`, `OPEN-014..016`, and `OPEN-021`. The following remain explicitly open: the vertical datum of `VPP.alt_m`, intermediate terrain-clearance policy for transfers, and overlap semantics between COP30 surface objects and explicit obstacles. These are not customer requirements.

## Source integration policy

- Start from exact `base_sha` on `dev`.
- Copy the exact `src/planes/model/itog_model/mvp_optimizator/**` snapshot from `grisha_source_sha`; do not merge its divergent history.
- Use TER-001 as the reference for constant-AGL profiles, configurable 25 m sampling, finite-elevation validation, explicit units/CRS, and intentional flat/no-terrain compatibility. Do not copy the legacy optimizer architecture.
- Keep `src/planes/model/itog_model/mvp_optimizator/` as the only resulting optimizer.
- Consolidate `planner.io.dem` into the package `planner/io/dem/`; remove the conflicting legacy `planner/io/dem.py` module.

## Architecture and ownership

```text
survey geometry -> bbox -> integration acquisition -> cached COP30 GeoTIFF
    -> canonical DEM provider -> terrain profile -> Swath/SwathSegment
    -> existing Grisha physics -> matrices -> routing -> validator
```

- Integration owns HTTP, bbox derivation, cache, atomic download, and downloaded-raster validation.
- Model owns local elevation providers and a single terrain profile.
- Grisha physics alone owns time and energy. Terrain geometry may expose 3D distance as a diagnostic but must not add a second time/energy penalty.
- COP30 is a digital surface model (DSM), not guaranteed bare-earth terrain.
- Explicit obstacles remain a separate layer.
- Wind, assignment, clustering, routing, multi-flight, LNS, catalog, optimization criteria, and rotor/fixed-wing physics are unchanged except for an unavoidable import-only terrain plumbing change, if any.

## Terrain rules

- Survey altitude uses `h_ASL = h_surface + h_AGL`.
- `h_AGL` continues to come from the existing GSD/camera calculation.
- Sampling step is configurable, strictly positive, and defaults to `25.0 m` (expert guidance: approximately 20–30 m).
- Sampling includes both endpoints and uses `ceil(horizontal_distance / step)` intervals.
- A requested terrain source fails closed for missing files, bad KML/GeoTIFF, missing optional raster support, nodata, non-finite values, invalid transforms, and samples outside coverage.
- Terrain intentionally absent may use explicit flat terrain for backwards compatibility.
- Local KML and GeoTIFF workflows continue through `params.dem_file`.

## OpenTopography acquisition

- Use the Global Datasets API with `demtype=COP30` and `outputFormat=GTiff`.
- Derive west/east/south/north from survey polygons only; union multiple survey polygons.
- Optional bbox padding is configurable, defaults to zero, and is documented in metres.
- Read `OPENTOPOGRAPHY_API_KEY` only from the environment and never place its value in logs, exceptions, filenames, metadata, or Git.
- Cache outside the repository, with optional `PLANES_TERRAIN_CACHE_DIR` override and a SHA-256 key over dataset and normalized bbox.
- Download to `.part`, validate, then atomically replace the final `.tif`; delete partial files on failure.
- Reusing the same valid cached area performs zero HTTP requests.
- The optimizer never performs network access and never requests per-point elevations.

## Limitations

- COP30 has nominal 30 m source resolution; 25 m sampling does not create 25 m source resolution.
- No new intermediate transfer terrain-clearance rule is introduced.
- No VPP datum conversion is invented.
- DSM/explicit-obstacle overlap remains unresolved.
- No certified terrain avoidance or flight-safety claim is made.
- Wind semantics are not redesigned.
