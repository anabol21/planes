# INT-002 — fast-forward dev to canonical main before TER-001

## Purpose

Synchronize `dev` with the canonical `main` history so TER-001 can target `dev` without branching from a stale tree. This is a repository synchronization task, not a feature merge.

No source-derived requirement behavior changes. No `OPEN-*` item is resolved by moving the ref.

## Verified preconditions

At the 2026-09-25 pre-sync audit:

- source `origin/main`: `e4ec3fa825f08eb9136c9c0c283904c4187c380a`;
- target `origin/dev`: `4c459a6c8e1383f1fbf8b87d2416686e3cfab866`;
- `git rev-list --left-right --count origin/dev...origin/main`: `0 23`;
- `git merge-base origin/dev origin/main`: `4c459a6c8e1383f1fbf8b87d2416686e3cfab866`;
- `git merge-base --is-ancestor origin/dev origin/main`: success;
- `git push --dry-run origin origin/main:refs/heads/dev`: accepted as `4c459a6..e4ec3fa`.

Therefore the permitted operation is a true fast-forward of `dev` to the exact canonical `main` SHA above.

## Scope

- Refresh remote refs immediately before the push.
- Re-check that `dev` has zero unique commits and is an ancestor of the declared source SHA.
- Update `dev` using a normal fast-forward push only.
- Fetch again and verify the remote SHA and ancestry.
- Validate the workspace from the synchronized `dev` state.
- Make the already-reviewed TER-001 governance documentation available on `dev` as a separate documentation-only fast-forward after the canonical sync is verified.

No source-code or contract modification is authorized. Contract version remains `v0`.

## Explicit exclusions

Do not include, merge, cherry-pick, or rebase unmerged feature branches, including:

- `origin/cursor/solver-pipeline-integration-c21d` (`87646e1d4875e2305157146463d00c6e2286156e`);
- `origin/cursor/kml-field-stitch-e347` (`f2874eed8ebf010c1fd9c349f7dc58bc09cadd99`);
- `origin/GreforyAbdr-patch-1` (`4f9775131b48ffc3e2aaf0a253f2ee6c3a64a4a8`).

They may appear on `dev` only if they independently enter the declared canonical `main` history before a refreshed pre-push audit. If the source SHA changes, update this brief or stop for maintainer review; do not silently expand the sync.

## Stop conditions

Stop without modifying `dev` if any of these occurs:

- refreshed `origin/dev` has a unique commit relative to the declared source;
- `origin/dev` is not an ancestor of the declared source;
- canonical `origin/main` no longer equals `source_sha`;
- the update would create a merge commit, require a rebase, or require force;
- GitHub branch protection or a server hook rejects the normal push;
- unexpected commits or files appear in the proposed range.
