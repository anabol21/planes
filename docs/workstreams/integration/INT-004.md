## Goal

Provide one executable Scenario v0 transport from the browser through backend validation,
immutable SQLite persistence, worker claim, runtime adapter HTTP serialization, and runtime
parsing. Every supported field must reach the runtime domain boundary without silent removal.

## Scope

1. Freeze an executable Scenario v0 with explicit coordinate, speed, distance, direction, GSD,
   and obstacle-height units.
2. Serialize current form state into the shared scenario without optimizer-specific structures.
3. Validate the request at the backend and preserve its scenario and optimization objects as
   immutable JSON snapshots.
4. Pass the exact snapshot through the worker and runtime HTTP client.
5. Validate and parse the complete scenario at the runtime server before the solver boundary.
6. Keep unsupported legacy-optimizer mappings explicit and local to its adapter boundary.
7. Add one shared golden fixture and deterministic layer and vertical transport tests.

## Team decisions

- `EPSG:4326` remains the browser geometry CRS for v0.
- Polygon coordinates use GeoJSON order `[longitude_deg, latitude_deg]` and closed linear rings.
- `optimization.objective` is the sole public optimization-criterion field; the legacy adapter
  maps it to its existing internal criterion token.
- Equipment remains selected by catalog `model_id` and `camera_id`; this task does not duplicate
  catalog physics in the public request.

These are integration decisions, not customer requirements.

## Explicitly out of scope

- TER-GRI or any other optimizer integration;
- terrain acquisition or terrain-profile calculation;
- physics, routing, assignment, or optimization-criterion algorithms;
- fleet-catalog redesign;
- frontend map rendering;
- changing the bearer-token architecture or committing credentials.

## Acceptance criteria

- The golden request contains two survey areas, a restricted zone, two obstacles, two aerodromes,
  two board cards with different cameras, non-default survey settings, wind, objective, and seed.
- Frontend, backend, worker, runtime HTTP, and runtime parser consume the same fixture semantics.
- SQLite reload is equal to the accepted request objects.
- A capture solver receives every scenario field after a real local HTTP round trip.
- Unsupported versions and malformed scenarios fail explicitly.
- The current legacy optimizer path remains available; unsupported geometry is documented at its
  adapter boundary and is not dropped by transport.
- Frontend tests/typecheck/build, backend tests, relevant runtime tests, workspace validation, and
  `git diff --check` pass, or unavailable platform-specific checks are reported as not run.
